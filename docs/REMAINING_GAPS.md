# NCAA remaining gaps and acceptance checks

Updated 2026-10-14. Target: NCAA Football 10 PSP US, ULUS10440, AOT C++/WebAssembly. Default guest RAM is 64 MiB, with a 56 MiB user partition. This checklist tracks evidence, not a promise of full compatibility.

Latest rendering evidence: byte-channel texture functions now have software/GLES regressions across all five functions, RGB/RGBA, doubling, alpha tests and perspective constant colors. These targeted corrections slightly worsen full-frame RGB MAE: SDSU 0.5737 → 0.5854 and Georgia Tech–Georgia 1.0227 → 1.0445. Prefix 39 still matches exactly; original draw 39 introduces the first mismatch. Separate fixed-point blend products predict 96.36% of its lower-field reference pixels exactly, supporting blend precision as the next target. Native captures verify RGBA8 and presentation agrees with direct RGB565 output. Earlier RGBA4444 color metrics remain superseded. Latest package `build/static-ncaa10-texture-functions` passes web/package/native checks. Fresh browser gameplay/FPS remains pending Chrome app access. GPU blend rounding/post-blend dithering/packing, alpha/stencil precision and complete hardware agreement remain open. See [reference evidence](PPSSPP_REFERENCE.md).

The next rendering implementation should start with an actual-display-list regression for source `(40,63,16)`, destination `(121,154,72)`, source alpha 21 and expected `(114,146,67)`. Extend it across add/subtract/reverse-subtract, factor boundaries and overlapping primitives. Exact products must be rounded separately, then combined before dither, saturation and target packing; subtracting a constant from the source is not equivalent.

For WebGL2, design an ordered GPU destination snapshot/resolve path where fixed-function blending cannot represent those operations. Preserve stencil/depth and target aliasing, keep copies on the GPU, and split or otherwise handle overlapping primitives so each observes preceding output. Measure copy area, draw/batch counts, GPU time and sustained foreground gameplay before accepting its performance. Recompare the same corrected prefixes and complete frames, retaining both better and worse results. The broader pacing/audio, controls, saves and mode acceptance checks above remain required.
